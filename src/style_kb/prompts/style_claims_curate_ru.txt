Ты проверяешь уже извлечённые StyleClaim из обучающего видео о мужском стиле.

Цель: дать решения для аудита и безопасной пост-обработки. Не извлекай новые знания и не переписывай canonical claims.

Вход содержит список claims после точной дедупликации. Каждый claim уже привязан к источникам в коде, но тебе передаются только смысловые поля.

Что можно делать:
1. Пометить semantic duplicate: если два claims выражают одно и то же правило или одно и то же определение другими словами, один оставь keep=true, у второго поставь keep=false и merged_into=<claim_id оставленного>.
2. Перекалибровать confidence: high, medium или low.
3. Пометить split_candidate=true, если claim склеивает две независимые мысли.
4. Дать split_suggestion как короткие варианты разделения, только для аудита.
5. Дать rewrite_suggestion только если формулировка явно слишком широкая, но это предложение для аудита, не canonical текст.
6. Дать applies_to_note, если applies_to выглядит слишком широким, слишком конкретным или непоследовательным.

Жёсткие ограничения:
1. Не добавляй новые claims.
2. Не меняй claim, rationale, evidence, prefer, avoid, topics или applies_to.
3. merged_into указывай только если смысл совпадает, а не просто совпадает тема. При сомнении оставь оба keep=true.
4. Не сливай definition с rule/recommendation, если один claim определяет термин, а другой говорит о применении или следствии.
5. split_candidate ставь только когда внутри одного claim есть две независимые применимые мысли, обычно связанные словами «но», «при этом», «одновременно», «а в целом».
6. confidence="high" — только для прямо подтверждённого утверждения; "medium" — для вероятностных тестов, обобщений одной фразы или визуальной интерпретации; "low" — для слабой опоры.
7. Если нет замечаний, верни keep=true, merged_into="", исходный confidence, split_candidate=false, пустые строки/массивы для suggestion/note.

Формат ответа:
{
  "decisions": [
    {
      "claim_id": "claim id from input",
      "keep": true,
      "merged_into": "",
      "confidence_revised": "high",
      "confidence_reason": "короткая причина на русском",
      "split_candidate": false,
      "split_suggestion": [],
      "rewrite_suggestion": "",
      "applies_to_note": ""
    }
  ]
}

Верни одно решение для каждого входного claim. Возвращай только валидный JSON без markdown и пояснений.
