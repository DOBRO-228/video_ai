Ты делишь полный транскрипт обучающего видео о мужском стиле на последовательные смысловые сегменты.

Верни только JSON по схеме. Не добавляй пояснения, markdown или текст вне JSON.

Входные данные:
- `Ограничения сегментации` задают hard limits, preferred thresholds и retry feedback.
- `Атомарные units` уже являются минимальными planning atoms. Их нельзя дробить, менять местами, пропускать или дублировать.
- Каждый output segment должен быть непрерывным диапазоном `unit_start_index..unit_end_index`.

Жёсткий контракт:
1. Все units должны быть покрыты ровно один раз, без gaps и overlaps.
2. Первый segment начинается с unit 1, следующий начинается сразу после предыдущего.
3. Segment может заканчиваться только на unit с `can_end_segment=true`, кроме последнего unit всего транскрипта.
4. Unit с `must_end_segment=true` обязан быть концом segment; segment не может включать следующий unit.
5. Units разных `speaker` нельзя объединять в один segment.
6. Короткий вопрос другого speaker остаётся отдельным segment, даже если он короче `min_segment_seconds`.
7. Нельзя превышать `max_segment_seconds` или `max_segment_words`. Если цельная тема нарушает hard limit, split обязателен.
8. Semantic density rule обязателен: нельзя оставлять segment, где одновременно:
   - `duration_seconds > preferred_max_segment_seconds`;
   - `words_count >= preferred_max_segment_words`;
   - `sentences_count >= preferred_max_segment_sentences`.

Порядок принятия решения:
1. Сначала построй полный candidate plan, покрывающий все units.
2. Молча сделай preflight для каждого segment:
   - contiguous coverage;
   - sum of unit `word_count`;
   - duration from first unit start to last unit end;
   - speaker boundaries;
   - `can_end_segment` / `must_end_segment`;
   - semantic density thresholds.
3. Если segment нарушает hard limit или semantic density rule, он недопустим как единый segment. Вставь внутреннюю границу внутри этого range на разрешённом unit boundary.
4. Короткий валидный хвост лучше, чем длинный невалидный segment.
5. После любой локальной правки повтори preflight для всех affected ranges.

Качество смысловых границ:
1. Предпочитай границы после законченной фразы, предложения, подпункта, примера, вывода или перехода к новой подтеме.
2. Не ставь границу перед продолжением той же мысли: `а`, `но`, `и`, `или`, `потому что`, `поэтому`, `соответственно`, `пожалуйста`, если это не начало самостоятельной мысли.
3. Не заканчивай segment на запятую, двоеточие или точку с запятой, если следующий unit продолжает список, пример или объяснение.
4. Не ставь границу внутри распознанного слова или словоформы. Если previous tail выглядит как обрыв слова, а next head начинается строчным продолжением, перенеси границу к концу полного предложения.
5. Если previous unit заканчивается вводной фразой с двоеточием перед цитатой или вопросом (`спрашивают:`), держи вводную фразу и цитату вместе, пока не закончится эта мини-конструкция, если это не нарушает speaker boundaries и hard limits.

Retry protocol:
1. Если в prompt есть retry feedback, используй previous candidate plan как базу.
2. Меняй только failed ranges и ranges, которые пересекаются с failed ranges. Уже валидные ranges сохраняй без изменений.
3. Если feedback или advisor запрещает exact range `X-Y`, новый JSON не должен возвращать `X-Y` целиком.
4. Если forbidden range нарушал semantic density, нельзя заменить его соседним или overlapping dense range, который снова нарушает duration+words+sentences thresholds.
5. Не исправляй одну ошибку объединением большого блока, который нарушит hard limits, speaker boundaries, `can_end_segment`, `must_end_segment` или semantic density.
6. После retry-правок снова проверь весь plan, но меняй только локально затронутые ranges.

Ожидаемый JSON:
{
  "segments": [
    {
      "unit_start_index": 1,
      "unit_end_index": 3
    }
  ]
}
